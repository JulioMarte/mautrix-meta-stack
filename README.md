# mautrix-meta stack for Coolify

Minimal, reproducible deployment of **Synapse + mautrix-meta** for testing Facebook Messenger / Marketplace bridging on Coolify.

This repository intentionally uses the official prebuilt images instead of compiling mautrix-meta from source.

## What this deploys

```text
Internet
   |
   v
Coolify / Traefik
   |
   +--> Synapse :8008   (public through your Matrix domain)
            |
            | private Coolify network
            v
       mautrix-meta :29319   (internal only)
            |
            v
        Meta / Facebook
```

The initial PoC uses SQLite for both Synapse and mautrix-meta. That is deliberate: validate authentication, Marketplace sync, inbound/outbound messaging, restart recovery and backfill before introducing PostgreSQL.

## Versions

The defaults are pinned in `.env.example` and `compose.yaml`:

- Synapse: `matrixdotorg/synapse:v1.160.0`
- mautrix-meta: `dock.mau.dev/mautrix/meta:v26.07`

Do not switch to `latest` casually. mautrix documents that its `latest` tag points to the latest commit rather than necessarily the latest stable release.

## Prerequisites

- A VPS already managed by Coolify.
- Docker available on that VPS.
- A DNS name for Synapse, e.g. `matrix.example.com`, pointing to the VPS.
- SSH access to the VPS for the one-time bootstrap.
- A Matrix MXID that will be the initial bridge administrator, e.g. `@admin:matrix.example.com`.

## 1. Bootstrap once on the Coolify server

Clone this repository on the VPS or copy `scripts/bootstrap.sh` there, then run:

```bash
export MATRIX_SERVER_NAME=matrix.example.com
export MATRIX_ADMIN_MXID=@admin:matrix.example.com
export STACK_DATA_ROOT=/data/mautrix-meta-stack

sudo -E bash scripts/bootstrap.sh
```

The script follows the official Docker bootstrap flow:

1. Generates Synapse `homeserver.yaml` and signing keys.
2. Generates mautrix-meta `config.yaml`.
3. Configures the bridge for Facebook, Marketplace spaces, Docker-internal addresses and SQLite.
4. Generates the mautrix appservice `registration.yaml`.
5. Copies that registration into Synapse's persistent `appservices/` directory.
6. Adds the registration path to `homeserver.yaml`.
7. Sets ownership expected by the official images.

Runtime/secrets are stored under `${STACK_DATA_ROOT}` and are **not committed to Git**.

## 2. Add the repository to Coolify

Create a new Git-based Docker Compose resource and point it at this repository.

Use:

- Branch: `main` after the deployment PR is merged.
- Compose file: `compose.yaml`.
- Build pack: Docker Compose.

Set these Coolify environment variables:

```env
MATRIX_SERVER_NAME=matrix.example.com
MATRIX_ADMIN_MXID=@admin:matrix.example.com
STACK_DATA_ROOT=/data/mautrix-meta-stack
TZ=America/Santo_Domingo
SYNAPSE_IMAGE=matrixdotorg/synapse:v1.160.0
MAUTRIX_META_IMAGE=dock.mau.dev/mautrix/meta:v26.07
```

`MATRIX_SERVER_NAME` and `MATRIX_ADMIN_MXID` are primarily bootstrap/documentation values. The runtime configuration lives in the persistent files generated by the bootstrap.

## 3. Configure the public domain in Coolify

Expose **only Synapse**.

Assign the Synapse service a domain with internal port `8008`, for example:

```text
https://matrix.example.com:8008
```

Coolify/Traefik terminates public HTTPS; the `:8008` tells Coolify which internal container port to route to.

Do **not** assign a public domain to mautrix-meta and do not publish port `29319`.

## 4. Create the initial Matrix user

After Synapse is healthy, create a local Matrix user from the Synapse container. A typical Synapse command is:

```bash
register_new_matrix_user -c /data/homeserver.yaml http://localhost:8008
```

Create the MXID configured as `MATRIX_ADMIN_MXID` during bootstrap. You can run the command using Coolify's terminal for the Synapse container.

For a PoC, do not enable open public registration.

## 5. Verify both services

Synapse:

```text
https://matrix.example.com/_matrix/client/versions
```

mautrix-meta is intentionally internal. Its readiness endpoint is:

```text
http://mautrix-meta:29319/_matrix/mau/ready
```

The Compose healthchecks verify both automatically.

You can also run:

```bash
STACK_DATA_ROOT=/data/mautrix-meta-stack bash scripts/check-config.sh
```

## 6. Authenticate Facebook

Once you can log into the Matrix homeserver with a Matrix client, open a management room with the Meta bridge bot and follow the current mautrix-meta authentication flow.

For this stack, `network.mode` is set to `facebook` and `network.marketplace_space` is enabled.

The initial validation target is intentionally narrow:

```text
Facebook login
    -> existing Messenger/Marketplace chats sync
    -> new inbound message reaches Matrix
    -> Matrix reply reaches Facebook
    -> restart both containers
    -> bridge reconnects
    -> missed Marketplace messages backfill
```

Do not add Chatwoot until those checks pass reliably.

## Persistent data and secrets

Default host paths:

```text
/data/mautrix-meta-stack/
├── synapse/
│   ├── homeserver.yaml
│   ├── *.signing.key
│   ├── homeserver.db
│   ├── media_store/
│   └── appservices/
│       └── mautrix-meta.yaml
└── mautrix-meta/
    ├── config.yaml
    ├── registration.yaml
    └── mautrix-meta.db
```

Treat the entire directory as sensitive. In particular, `registration.yaml`, signing keys, SQLite databases and bridge config must never be committed.

## Backups

Before upgrades, back up `${STACK_DATA_ROOT}`. For the PoC a filesystem-level backup while containers are stopped is sufficient. Before production/multi-tenant use, move both services to PostgreSQL and design proper database + media backups.

## Important operational constraints

- **One mautrix-meta instance per data directory.** Do not horizontally scale the bridge container against the same state.
- Keep Synapse and mautrix-meta in the same Compose stack so Coolify gives them private service-name DNS (`synapse`, `mautrix-meta`).
- Do not expose the appservice port publicly.
- Do not commit generated configuration, appservice registration, access tokens or databases.
- SQLite is for this PoC, not the intended multi-tenant production database.
- Meta is an unofficial bridge target; protocol changes can temporarily break sync. Treat the PoC as a reliability test, not proof of production SLA.

## Upgrade procedure

1. Read the upstream mautrix-meta and Synapse release notes.
2. Back up `${STACK_DATA_ROOT}`.
3. Change the pinned image version in Coolify or `.env.example`/`compose.yaml` defaults.
4. Redeploy.
5. Confirm both healthchecks and perform an inbound/outbound Marketplace test.

Never blindly track `latest` for mautrix-meta.

## Repository purpose

This is a deployment repository. Upstream mautrix-meta source code does not belong here unless the project intentionally decides to maintain a fork. The normal deployment consumes the official mautrix Docker image.
